# mesh 导入 · 全局导航规划（`mesh_nav.html`）

一个独立页面：载入任意 OBJ / STL 模型（含多层楼梯），页面自己判断哪是地板、哪是墙，然后在可通行面上做 2.5D A*。

## 现在能做的

| 能力 | 状态 |
|---|---|
| 导入 OBJ / STL（ASCII + 二进制） | 可用 |
| 三角面按法向分成水平面 / 竖直面 | 可用 |
| 每列的地板高度、墙投影 + 膨胀距离场 | 可用 |
| 可通行面（黄）与膨胀后的墙（红）可视化 | 可用 |
| 点模型设起点 / 终点 | 可用 |
| 分辨率、膨胀半径可调 | 可用 |
| 2.5D A* 跨层规划 | **未跑通** |

## 判定规则

- 水平面（`|nz| > 0.65`）：这一列有地板，站在这个高度。薄板会报告顶面和底面两个高度，按 0.10 m 分组取顶面。
- 竖直面（`|nz| < 0.35` **且 z 跨度 > 0.35 m**）：算墙。0.19 m 的踢面不算，否则它会把自己所在的那跑楼梯膨胀掉。
- 膨胀：墙投影到 XY 后做距离场，只往「没有地板」的列扩散——平台顶那种四面是墙、但确实能站的地方要保住。
- 相邻两列高度差 ≤ 0.40 m 才连边。一级台阶 0.19 m 过得去，一层楼 3.42 m 过不去。

## 已经在示例上修掉的三个 bug

1. **台阶踢面被当墙膨胀。** 0.19 m 高的竖直面按 0.45 m 膨胀，把整跑楼梯封死。加 z 跨度门槛后解除。
2. **合并阈值 0.20 m 大于级差 0.19 m。** 两级并成一级，落差变 0.38 m，楼梯整段走不通。降到 0.10 m。
3. **同一列的高低面之间没有边。** 薄板顶面和底面被记成两个高度，起点吸附到底面后就永远上不到自己脚下那层楼板。已加同列垂直边。

## 现在卡在哪

示例四层模型（`example_four_floor.obj`，293 个盒体、3,516 面、3 段楼梯）上，起点在 1F、终点在 4F，A* 展开约 3,700 个节点就耗尽，判定无路。

已确认的部分：

- 楼梯被正确识别：楼梯井 516 列，其中踏面列的高度序列是 `[0, 0.19, 1.09, 3.42, 3.61, 4.49, 6.84, 7.03, 7.89]`，级差 0.19 m。
- 楼板高度正确：`[-0.1, 0, 3.3, 3.4, 6.7, 6.8, 10.2]`，四层各 3.4 m。
- 膨胀为 0 时 `blocked` 为 0，所以不是膨胀堵死。

没确认的：起点那一层的可通行列是否真的与楼梯底部连成一串，以及 A* 邻接里「同一列不同高度」这条边有没有真正参与搜索（加上之后展开节点数没变，这一点本身可疑）。

## 下一步方向

- 把「同列垂直边」用最小用例单独验证，确认它进了搜索而不是被前面某个 `continue` 挡掉。
- 若确认连通性没问题，把 A* 换成「先按层分区、再用楼梯作为区间的桥」的分层图搜索，比在 2.5D 栅格里硬搜省得多。
